# 터치 드리블 마무리 (지시서)

## 배경
공을 발 앞에 붙여 미끄러뜨리던 드리블을 **터치 드리블**로 바꾸는 중이다 (커밋 `867d268 WIP`).
공은 굴러가고(구름 감속) 선수가 따라가 발이 닿을 때 다시 툭 찬다. 기본 동작(터치 반복, 질주 시 길게 치고 나가기, 멈추면 발로 세우기, 너무 멀어지면 소유 상실)은 동작한다.

관련 코드 (모두 `src/gameplay/Match.ts`):
- `carryBall(dt, touches)` → `touchDribble(o, dt)`: 터치 판단과 공 속도
- `handleUser()` 안 `// 공을 가진 채 손을 떼면 …` 블록: 손 뗌(트래핑)과 공 쪽으로 끌어당기기(pull)
- 상수: `src/config.ts` 의 `DRIBBLE`
- 테스트: `tests/dribble.test.ts` (현재 1개 실패), 시뮬레이션: `tests/simulation.test.ts`, `tests/motion.test.ts`
- 옵션: `MatchOptions.dribbleTouches` (기본 켜짐)

## 고칠 버그: 드리블 중 방향 전환이 안 된다 (사용자 실제 플레이에서 확인)
원인 (분석 완료):
1. `handleUser` 의 pull: 공이 발끝에서 0.35m만 떨어져도 이동 입력을 공 쪽(= 지금까지 진행 방향)으로 끌어당긴다. 방향키를 꺾어도 몸이 돌지 않는다.
2. `touchDribble` 의 터치는 공을 `o.facing`(몸 방향)으로 보낸다. 몸이 안 돌았으니 공도 원래 방향으로 간다.
→ 몸이 안 돌아서 공이 안 돌고, 공이 안 돌아서 몸이 끌려가는 교착.

## 해야 할 것
1. **의도 방향으로 터치**: 터치할 때 공을 몸 방향이 아니라 **드리블 의도 방향**으로 보낸다.
   - 사용자: 이번 프레임 이동 입력(`cmd.move`, 크기 > 0.1일 때). AI: `TeamAI` 가 정한 드리블 목표 방향 (지금은 `p.facing`/`p.vel` 로 대신해도 됨 — AI 쪽 변화는 최소화).
   - `Match` 에 `dribbleIntent: THREE.Vector3` 같은 상태를 두고 `handleUser` 에서 갱신, `touchDribble` 에서 사용.
   - 한 번의 터치로 꺾을 수 있는 최대 각도는 능력치로 제한: 약 60°(낮음) ~ 120°(드리블·민첩성 높음). 더 큰 각도는 여러 번의 터치로 나눠 꺾인다.
   - 꺾는 터치는 공 속도를 줄인다 (예: 꺾는 각도 90°면 기존 터치 속도의 0.6배). 몸 방향(`facing`)도 터치 방향 쪽으로 즉시 일부 돌린다(예: 50%) — 실제로 몸을 틀어 공을 접는 느낌.
2. **pull 정리**: 공이 발이 닿는 거리(`DRIBBLE.reach`) 안에 있으면 끌어당기지 않는다 (입력 그대로 → 몸이 돌고 → 다음 터치가 꺾음). 공이 reach 밖으로 굴러갔을 때만 공 쪽으로 휘어 쫓는다(지금 로직 유지).
3. **멈춤 트래핑을 터치로 계산**: `touchDribble` 의 `!moving` 분기(발로 세우기)에서 공 속도가 1 m/s 넘으면 `{ type: 'touch' }` 이벤트를 한 번 내고 `touchGap` 을 건다. (공 방향이 바뀌는 모든 순간 = 터치)
4. **터치 소리**: `src/core/Game.ts` `handleEvents` 에 `case 'touch'`: `this.sound.play('kick', Math.min(0.25, 0.08 + e.speed / 60), 1.25)` 정도의 작은 소리.
5. **AI도 같은 규칙**: AI 소유자도 의도 방향 터치를 쓴다. AI 대 AI 시뮬레이션에서 공 소유 상실(헤비 터치)이 과하지 않게 (`DRIBBLE.leash` 초과로 잃는 횟수 경기당 40회 이하).

## 완료 조건 (모두 자동 검증)
- `tests/dribble.test.ts` 전부 통과. 다음 테스트를 **추가**:
  - 정지 상태에서 공을 가진 채 ↑로 1초 달린 뒤 →(90°)로 꺾으면 1.0초 안에 공 속도 방향이 → 쪽(±30°)이 된다.
  - 같은 상황에서 180°(↓)로 꺾어도 2.0초 안에 공이 ↓ 쪽으로 가고 소유를 잃지 않는다.
  - 드리블 능력치가 높은 선수가 낮은 선수보다 90° 전환이 빠르다 (공 방향이 바뀌기까지 걸린 시간).
  - 공 방향이 0.2rad 넘게 바뀌는 모든 스텝에 `touch` 이벤트가 있다 (기존 테스트, 지금 실패 중).
- 기존 테스트 전부 통과 (`pnpm typecheck && pnpm test && pnpm build`). 시뮬레이션 테스트의 기대값을 낮춰서 통과시키지 말 것 — 필요하면 이유를 커밋 메시지와 마지막 보고에 적는다.
- 브라우저 확인 스크립트 `scripts/dribble-smoke.mjs` 작성: 실제 키 입력(ArrowUp 1초 → ArrowRight 1.5초)으로 공 진행 방향이 바뀌는지 수치로 출력. Codex 샌드박스에서 Chrome 실행이 막히면 "미실행"으로 보고하고 재시도하지 않는다.
