## 1. 개인기가 "안 되던" 원인 (2026-10-17 수정·배포)
실제 경기 화면에서 키를 눌러 확인한 결과:
1. 달리던 방향키를 누른 채 Shift+↓를 누르면 →+↓ = ↘가 되어 어떤 커맨드와도 안 맞았다 → Shift/Z 이전부터 누르던 키는 탭 커맨드에서 빼고, 굴리는 커맨드(스텝오버)는 그 키를 '오래 누른 첫 칸'으로 읽는다. 둘 다 맞으면 긴 커맨드.
2. 기준 방향이 선수의 실제 각도라 조금만 비스듬해도 다른 방향으로 읽혔다 → 인벤 DB처럼 **바라보는 방향에 가장 가까운 화면 4방향 기준**.
3. 나가도 티가 안 났다 → 사용자 개인기는 HUD에 '★ 이름'.
남은 것: 개인기 몸동작이 범용 볼 컨트롤 클립이라 밋밋하다(전용 동작 데이터 없음) → 4단계.

## 2. 단계별 계획

### 1단계 — 기본 조작·공 받기 (체감 최우선, 내가 직접)
1. **녹온**: 질주 중 Shift 탭 = 공을 길게(4~6m) 치고 가속, EE = 짧은 녹온, EEE = 더 긴 녹온. 녹온 거리·가속은 능력치(가속·속력·드리블).
2. **공 받기**
   - 패스 키 미리 누름(원터치 예약) 때 공을 지나치지 않게: 예약 중에도 가로챌 지점에서 감속, 공이 몸 뒤로 가면 예약 취소 후 첫 터치.
   - 멈춰 받을 때 공을 발 앞으로 끌어와 세우기(지난번 시도는 AI 경기 테스트를 깨서 되돌림 → 사용자 조작 선수부터 적용하고 AI 테스트로 확인).
   - Ctrl+방향 퍼스트 터치 녹온, 받는 순간 트래핑 동작(trap 클립 80개 이미 구워짐) 연결.
3. **C 볼 키핑**: 공을 가진 채 C 유지 = 공과 상대 사이에 몸을 넣고 느리게 버티기(속도 ~60%, 태클 성공률 낮춤, 몸싸움 능력치). 상대 쪽을 등지도록 몸 방향 자동.
4. **수비 Shift+방향 선수 전환**: 화면 방향으로 가장 가까운 동료로 바꿈(오른쪽 스틱 전환과 같음).
5. **킥오프**: 센터 서클에 공격 팀 2명, 상대는 서클 밖. 첫 패스(S, 옆/뒤)로 시작. AI 팀 킥오프도 첫 패스. 휘슬 전에는 대기.
6. **휘슬**: 합성 휘슬(약 3.2kHz + 구슬 떨림)로 공식 패턴 — 킥오프 짧게 1번, 전반 종료 길게 2번, 경기 종료 짧게 2번 + 길게 1번, 파울 짧게, 오프사이드 짧게 2번.

### 2단계 — 패스·슛 커맨드 채우기 (Codex)
- SS 딩크 패스(공을 살짝 띄워 앞 수비수의 발·태클을 넘기는 짧은 패스), WW 딩크 스루(같은 방식의 스루), Z+Q+W 낮은 로빙 스루, Q+S 침투 패스, C+S 플레어 패스.
- 크로스: A(기본) / A+A 낮은 / Q+A 높은 / C+A 플레어 / Z+A 빠른 — 박스 근처 측면에서만 크로스로 해석.
- 슛: D+D 드리븐(낮고 강하게), Z+D+D 감기는 드리븐, C+D 플레어(아웃프런트·라보나 연출), F+D+D 파워슛(긴 준비 + 정확도 게이지).
- 더블탭 판정 창(예: 0.25초)은 설정값으로, 플레이그라운드 스크립트 테스트로 검증.
- 수비: Space 유지 당기기, D 걷어내기·밀치기, C+방향 몸싸움, C+E 달리며 견제.

### 3단계 — 키퍼 (나 + Codex)
- `mocap-local/grf/deflect` 22개(높은 공 잡기·옆으로 쳐내기·무릎/가슴 높이 잡기 등)를 굽고, 공 높이·속도·거리로 **잡기 / 쳐내기 / 크로스바 위로 쳐내기 / 발 막기** 선택.
- 칩슛: 키퍼 위치·거리별 성공률 실측 → 뒷걸음질·점프 쳐내기 추가 → 키퍼 능력치(반응·핸들링·포지셔닝)로 차이.
- 공을 든 손 위치(양손 사이), 키퍼 S 던지기·Z+S 강한 던지기·D/A 드롭킥·W 공 놓기 동작.
- 스로인: 공을 머리 위 양손 사이에.

### 4단계 — 움직임·능력치 (나 설계, Codex 튜닝)
- **AcceleRATE**: 폭발형(키 ≤175cm, 민첩·가속 ≥80) / 균형형 / 지속형(키 큰 체격형) — 0→최고속 곡선이 다름. FC24 공식 기준을 따름.
- 속력 능력치 범위: 50 ≈ 7.5 m/s ~ 99 ≈ 9.5 m/s (실측 근거는 fc-mechanics.md).
- 드리블·민첩·밸런스: 회전 속도, 공을 둔 채 감속, 터치 간격·거리.
- 개인기 동작 품질: 별 높은 선수 배속(이미 일부), 자주 쓰는 개인기부터 전용 키프레임 다듬기.
- 플레이그라운드 스크립트로 선수별(★·능력치) 수치 비교표를 만들어 튜닝 근거로 남긴다.

### 5단계 — UI (Codex, 쉬움)
- 메뉴 레이아웃: 왼쪽 메뉴 열은 고정 폭·고정 위치, 오른쪽 내용은 자체 스크롤. 모바일은 높이에 맞게 접기·스크롤.
- 모바일 개인기 스틱(메모: `docs/CHECKLIST.md`).

## 3. 멀티플레이

### 3-1. 방식 선택
| 방식 | 장점 | 단점 |
|---|---|---|
| **입력 동기화 + 롤백 (권장)** | FIFA·격투게임 방식. 대역폭 아주 작음(입력만), 내 조작은 지연 0으로 반응 | 시뮬레이션이 모든 브라우저에서 비트 단위로 같아야 함, 롤백용 상태 저장·복원 필요 |
| 호스트 권한 + 상태 전송 | 결정성 불필요, 구현 단순 | 호스트 아닌 쪽은 공 다루기가 지연만큼 늦음(축구에서 치명적), 대역폭 큼 |
| 서버 권한(서버에서 시뮬레이션) | 치팅 방지 | 120Hz 물리를 서버에서 경기마다 돌리는 비용, 두 사람 모두 지연 |

→ **1:1 입력 동기화 + 롤백**을 목표로 구조를 준비하고, 결정성 검증이 끝나기 전까지는 호스트 권한 방식으로 먼저 붙여 볼 수 있게 둘 다 가능한 구조로 만든다.

### 3-2. 지금 코드에서 준비할 것 (순서대로)
1. **조작 주체 분리**: `Match.update(dt, cmd)` → `update(dt, cmds: [팀0 명령 | null, 팀1 명령 | null])`. 팀마다 `controlled`·충전 게이지·개인기 입력 상태를 따로(지금은 팀 0 하나만 가정, Match.ts 약 20곳).
2. **명령을 카메라와 무관하게**: 방향은 이미 월드 좌표로 바꿔 넘김(좋음). 명령을 작은 바이너리로 직렬화(버튼 비트 + 이동 각도 8비트 + 크기) → 틱당 4~6바이트.
3. **시뮬레이션과 화면 분리**: 판정이 화면용 값에 의존하는 곳 제거 — 예: 넘어지는 시간(`Player.fall()`)이 화면용 동작 길이·화면용 난수(`visualRandom`)로 정해짐 → 데이터 표에서 정해진 값으로.
4. **결정성**: 경기 난수는 이미 시드 고정. 브라우저마다 다를 수 있는 `Math.sin/cos/atan2/exp/pow`를 시뮬레이션 안에서는 결정적 구현으로 교체(공 물리는 cannon-es 대신 자체 적분으로 바꾸는 것도 검토 — 공 하나·충돌 단순). 같은 입력 기록을 Chrome·Safari·Firefox에서 돌려 상태 해시 비교하는 테스트.
5. **상태 저장·복원**: `Match.snapshot()` / `restore()` (선수·공·규칙·타이머·난수 상태). 롤백·재접속·리플레이에 공통으로 씀.
6. **틱 번호**: 고정 스텝마다 증가하는 틱 카운터, 네트워크 틱 60Hz(물리 120Hz면 2스텝 묶음).

### 3-3. 중계 서버 구성 (Cloudflare — 이미 Workers·D1 운영 중)
- **Worker (HTTP)**: 방 만들기·방 코드 입장·빠른 매칭 요청.
- **매칭 Durable Object 1개**: 대기열(실력·지역), 짝이 맞으면 경기 방 생성.
- **경기 방 Durable Object (경기마다 1개)**: 두 클라이언트의 WebSocket을 받아
  - 틱별 입력을 상대에게 즉시 전달(중계), 서버 수신 시각 기록
  - 시작 시드·팀·설정 배포, 준비 확인 후 동시 시작 신호
  - 1초마다 양쪽 상태 해시 비교 → 어긋나면 기준 쪽 스냅샷으로 재동기화
  - 끊김: 일정 시간 입력을 '마지막 입력 유지'로 채우고 재접속 시 스냅샷 + 이후 입력 전송
  - 경기 끝나면 입력 기록을 R2/D1에 저장(리플레이·분쟁 확인)
  - 위치: 첫 접속자 근처(locationHint)로 생성해 지연 최소화
- 대역폭: 입력 6바이트 × 60Hz ≈ 0.4KB/s/인 — 무료/저가 한도 안.
- 나중에 지연을 더 줄이려면: 방 DO는 신호·백업만 하고 WebRTC DataChannel P2P로 직접 입력 교환(Cloudflare TURN 대체 경로).
- 지연 처리: 입력 지연 2~3틱(33~50ms) + 롤백 최대 8~10틱. 롤백 시 화면은 보정 보간.

### 3-4. 테스트 계획
- 같은 입력 기록 재생 → 상태 해시 동일(헤드리스, 브라우저 3종).
- 인위적 지연·손실(50~150ms, 2%)을 넣은 두 클라이언트 시뮬레이션 → 해시 일치, 롤백 횟수·최대 깊이 측정.
- 플레이그라운드 스크립트 형식을 '입력 기록' 형식과 통일(리플레이 = 스크립트).

## 4. 진행 순서 제안
1단계(조작·공 받기·킥오프·휘슬) → 3단계 중 칩슛·키퍼 잡기 → 2단계(커맨드 채우기) → 6단계 구조 준비(1~3번) → 4단계 → 5단계 → 6단계 4~6번과 서버.
각 단계는 플레이그라운드 JSON 스크립트로 실제 키 입력 테스트를 만들고, 실제 경기 화면 키 입력 확인(Playwright)까지 끝낸 뒤 배포.
