# 애니메이션 끊김 개선 결과

`tests/anim-smooth.test.ts`에서 실제 `player.glb`와 `motions.json`을 로드하고 고정 시드로 60Hz 재생했다. 수치는 hips, spine, 왼쪽 thigh, shin, upper arm, forearm의 로컬 쿼터니언 회전 벡터를 프레임 간 차분한 뒤, 그 변화량(2차 차분)의 최댓값이다. 단위는 rad/frame²이며 낮을수록 덜 튄다. 변경 전 코드는 같은 테스트를 HEAD의 기존 구현으로 실행해 측정했다.

| 시퀀스 | 변경 전 | 변경 후 | 감소 |
| --- | ---: | ---: | ---: |
| 정지 → 질주 | 1.7680 | 0.1599 | 91% |
| 질주 → 정지 | 1.0275 | 0.1376 | 87% |
| 질주 중 180° 회전 | 0.3172 | 0.1540 | 51% |
| 달리며 슛 → 달리기 | 0.4282 | 0.1510 | 65% |
| 슬라이딩 → 일어나기 → 달리기 | 0.9646 | 0.1910 | 80% |
| 세리머니 → 킥오프 | 1.5006 | 0.0403 | 97% |

화면 yaw의 180° 목표 변경은 프레임당 최대 3.1416 → 0.1333rad(96% 감소)이다. 물리 `facing`과 킥 터치 시점은 수정하지 않았다.

원인은 속도 경계에서 즉시 바뀌는 이동 클립 가중치, 이동 클립의 서로 다른 발 위상, 앞 동작을 즉시 중단하는 구운 동작 전환, 세리머니 중단 시 클립 끝으로 재생 위치를 건너뛰는 처리, 화면 yaw에 물리 방향을 바로 대입하는 처리였다. 이동 클립 가중치와 발 위상을 맞추고, 동작 교차 전환과 관절 회전의 시각적 보간을 추가했다. GLTFLoader가 제거한 점을 반영해 오버레이 뼈 이름도 바로잡고, 구운 다이빙과 팔 오버레이의 중복을 막았다.

한계: 관절 회전 보간은 약 50ms의 시각적 지연을 만들 수 있다. 48m 밖 평상시 선수는 기존 30Hz 갱신을 유지하므로 그 거리에서는 여전히 포즈 계단이 보일 수 있다. 수치는 자동 테스트의 고정 시퀀스 결과이며 실제 브라우저 프레임 시간이나 주관적 체감은 측정하지 않았다.
