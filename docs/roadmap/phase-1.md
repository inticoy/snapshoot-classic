# 1단계: 터치 조작 (모바일)

## 목표
휴대폰/태블릿에서 플레이 가능하게 한다. FC 모바일·eFootball 모바일의 일반적인 배치를 참고.
- 화면 왼쪽: 플로팅 가상 조이스틱 (터치한 위치에 생성, 이동 방향/크기 → `UserCommand.move`)
- 화면 오른쪽: 버튼 — 슛(꾹 눌러 파워), 패스, 스루, 로빙, 질주(누르는 동안). 수비 시 라벨/기능 전환: 압박, 스탠딩 태클, 슬라이딩, 선수 변경 (키보드의 상황별 동작과 동일한 의미).
  - 감아차기/칩슛: 슛 버튼에서 위로 스와이프하며 떼면 칩슛, 옆으로 스와이프하면 감아차기 (간단히).
- 기존 `Input`/`UserCommand` 경로를 재사용: 터치 입력이 같은 ButtonState를 만들도록 추상화 (키보드와 동시 사용 가능).
- 메뉴도 터치로 조작 가능 (이미 클릭 지원 확인, 좌우 값 변경 버튼 터치 영역 확보).
- 세로 화면이면 "가로로 돌려주세요" 안내. 멀티터치(조이스틱 + 버튼 동시) 필수.
- 모바일 성능: `devicePixelRatio` 상한, 그림자 맵 크기/관중 수 축소 옵션(저사양 자동 감지 또는 설정 "그래픽 품질").
- HUD 키 안내는 터치 기기에서 숨김. 하단 이름 바/레이더가 버튼과 겹치지 않게 배치.
- 터치 기기 감지: `pointer: coarse` 미디어 쿼리 + 첫 터치 이벤트.

## 완료 조건
- Playwright 모바일 에뮬레이션(가로 844×390, hasTouch)으로: 메뉴 터치 → 경기 시작 → 조이스틱 드래그로 선수 이동 → 슛 버튼으로 슛 이벤트 발생을 확인하는 스크립트를 `scripts/`에 추가하고 통과
- 데스크톱 키보드 동작 회귀 없음 (`pnpm test` 통과)
- 커밋 (푸시 금지)

## 참고: 브라우저 검증
Codex 샌드박스에서는 Chrome 실행이 막힌다(SIGABRT/EPERM). Playwright 스크립트는 `scripts/`에 작성만 하고, 실행이 막히면 재시도하지 말고 "미실행"으로 보고한다. 검증은 vitest 시뮬레이션 테스트로 대신한다. 브라우저 실행은 사람이 검토 단계에서 한다.
