# 개인기 1차 구현·검증 결과 (2026-10-17)

1차 개인기 12개(좌우 포함)와 Z 패스 3종을 추가했다. 기존 개인기 5개를 포함해 17개 전체를 검증했다. 좌우 정의는 `mirror()`를 쓰며, 접촉 위치는 GLB 골격의 미세한 비대칭까지 반영해 별도로 굽는다. 클립을 고정해 난수·이동 속도에 따라 발 접촉이 달라지지 않게 했다. 뼈 오버레이 회전은 추가하지 않았다.

## 개인기별 측정

실제 `player.glb`를 Node의 GLTFLoader+MeshoptDecoder로 읽고 `SkinnedPlayerModel`과 `SkillRunner`, 물리 공을 함께 진행했다. 검사는 정지 120Hz/60Hz, 3m/s 120Hz, 7m/s 60Hz, 세 방향·네 시드를 사용한다. 이동 중에는 45프레임의 이동 애니메이션을 먼저 재생해 동작 전환까지 포함한다. 접촉 시각을 처음 넘긴 프레임의 발끝-공 중심 거리를 측정하며, 사이드 스텝은 3주기 접촉을 검사한다. 기준은 **0.25m 이하**다.

## 패스·AI 측정

아래 패스 값은 같은 선수·입력·게이지(0.55), 수동 보정, 100시드의 평균이다. 속도는 초기 수평 속도, 높이 항목은 초기 수직 속도이며 비행 중 최고 높이와는 다르다.

| 패스 | 커맨드 | 수평 속도 기본→Z (m/s) | 수직 속도 기본→Z (m/s) | 방향 오차 RMS 비율 |
|---|---|---:|---:|---:|
| 강한 땅볼 | Z+S | 14.913→18.641 | 0.400→0.120 | 1.150 |
| 강한 스루 | Z+W | 15.206→19.008 | 0.400→0.120 | 1.150 |
| 낮은 로빙 | Z+A | 19.285→26.785 | 8.074→5.813 | 1.150 |

보조·세미·수동 각각 3종의 속도·높이·수신자를 비교했다. 실제 키 입력에서도 킥 1회와 개인기 오인식 0회를 확인했다. AI는 정면(방향 내적≥0.65) 2m 안에 필드 수비 1명일 때 판단당 3.5% 확률, 5초 쿨다운으로 사용한다. 1,000개 독립 시드에서 34회(3.4%) 사용했고 별 제한을 지켰다. 옆·뒤·2m 밖·수비 2명·별 부족 조건에서는 사용하지 않았다.

## 검증과 한계

- `pnpm install`, `pnpm typecheck`, `pnpm test`, `pnpm build` 결과는 최종 검증 후 아래에 기록한다.
- 커맨드는 구현 정의와 독립된 표로 15종×3방향 전수 인식 검사, 페이크를 포함한 17종 실제 키 입력 검사(기술 이벤트 정확히 1회, 소유율 99% 초과, 소유 상실 0회, 종료 몸·공 방향)를 통과했다. 사이드 스텝은 반복 이동 거리·해제·방향 변경도 검사했다.
- 기존 기대값을 낮추지 않았다. 기존 “꾹은 탭 개인기가 아니다” 검사는 탭 목록에서 그대로 유지하고, 전체 목록에서 사이드 스텝이 정확히 1회 나오는 검사를 추가했다.
- 브라우저 캡처 **미실행**: `node scripts/skill-shots.mjs`가 지정된 캐시의 Chrome for Testing을 실행했으나 즉시 SIGABRT로 종료됐다. 스크립트는 17종 전체를 캡처하도록 확장했다. 실제 화면의 미적 품질은 확인하지 못했다.
- 전용 개인기 모션이 없는 동작은 범용 control/trap/turn 클립과 몸·공 궤적으로 근사한다. 발 접촉 수치는 측정한 조건의 결과이며 모든 가능한 이동 위상·태클·충돌 조합을 보장하는 수치는 아니다.
- ★4~5 개인기·저글링(2차)은 구현하지 않았다.
