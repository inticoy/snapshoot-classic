# 경기장 절차적 그래픽

외부 다운로드·추가 의존성 없이 Three.js 메시와 캔버스 텍스처로 만든다.
`src/config.ts`의 `STADIUM`은 시각 설정, `GRAPHICS`는 품질별 예산을 관리한다.
가상 광고 문구는 `src/data/StadiumAds.ts`에 있다.

## 구현

- 낮 하늘·얇은 구름·대기 원근과 태양/반구광의 색온도를 맞춘다. ACES 톤매핑을 유지하고 노출을 조절했다.
- 그림자 카메라는 실제 렌더 카메라의 지면 시선 교점을 추적한다. 광원 좌표의 텍셀 격자로 위치를 고정해 이동 중 흔들림을 줄인다.
- 중계 시 그림자 반경은 high 30m / low 32m, 카메라 높이 9m 미만에서는 9m / 12m다. 그림자 맵은 기존 2048² / 1024² 그대로다.
- 잔디는 줄무늬·미세 색 노이즈를 굽고, 마킹은 규격 데이터로 만든 별도 단일 메시다. high에서만 반복 범프맵을 사용한다.
- 골대는 시각 단면을 24각으로 부드럽게 하고 소켓을 추가했다. 그물은 경계가 고정된 처짐을 적용하고 high에서는 조명에 반응하는 실 리본, low에서는 선분으로 그린다. 기존 충돌체는 그대로다.
- 관중은 기존 상자 인스턴스와 응원 동작을 유지하고 그림자를 받는다. 좌석 사이 계단 통로, 뒤쪽 출입구·표지, 지붕·기둥·트러스·난간을 추가했다.
- 벤치·좌석·입체 코너 깃발·조명탑 램프와 사다리를 추가했다. 구조물은 재질/그림자 설정별로 합치며 좌석은 단일 인스턴스 메시다.
- high에서만 개별 좌석·보조 트러스·사다리·잔디 범프·PMREM 환경 반사·리본 그물을 표시한다. low 좌석은 저비용 띠로 대체한다. 품질 전환 시 GPU 환경 반사는 최초 high 선택 때만 굽는다.

`gameplay/`, `physics/`, `net/`에는 변경이 없다. 경기 시드 대신 기존 시각 난수원을 사용한다.

## 모바일 비용 추정

시각 난수 seed=42로 모든 경기장 메시를 순회한 기하 예산이다. 실제 화면의 컬링·그림자 패스·골대·선수는 제외했으므로 GPU 측정치나 FPS가 아니다.

| 경기장 | 기존 high | 변경 high | 기존 low | 변경 low |
| --- | ---: | ---: | ---: | ---: |
| 삼각형 | 62,280 | 199,324 | 16,488 | 26,248 |
| 재질 그룹 기준 드로콜 | 92 | 45 | 92 | 42 |

관중의 빈자리 난수에 따라 삼각형 수는 조금 달라진다. low는 약 9,800개 삼각형이 늘지만 드로콜이 약 54% 감소한다. 잔디 색 텍스처는 3552×2304에서 2048×1328로 줄여 RGBA8 밉 포함 약 42MiB에서 14MiB로 감소한다. 마킹 선명도는 메시로 보완한다. 픽셀 비율·그림자 맵 크기·광원 수는 기존 수준이며 추가 렌더 패스는 없다. CPU 제출 비용과 텍스처 메모리는 줄고 기하 비용은 늘므로, low 모바일 성능은 대체로 유사하거나 CPU 병목 기기에서 개선될 것으로 예상한다. high는 좌석·리본·범프·반사로 GPU 비용이 증가한다.

## 검증과 시각 확인

`tests/stadium-visuals.test.ts`는 그림자 추적과 텍셀 고정, 품질 전환의 메시 예산, 합성 기하의 유효성, 품질 변경·그물 출렁임 전후 충돌체 불변을 검사한다.

이번 작업 환경에서는 Vite의 포트 바인딩이 `listen EPERM`으로 거부됐고 Playwright 캐시의 Chrome for Testing도 실행 직후 종료됐다. 따라서 실제 스크린샷·FPS·모바일 실기 검증은 완료하지 못했다.

실행 가능한 환경에서는 `pnpm dev` 후 TV 중계/넓은 중계/선수 뒤 카메라, 연습장 근접 카메라, 골대 양쪽, high↔low 전환을 확인한다. 특히 그림자 영역 가장자리, 관중석 지붕 아래 음영, 그물의 먼 거리 가독성을 확인한다.

자동 검사 결과: `npx vitest run` 42개 파일·482개 테스트 통과, `npx tsc --noEmit` 통과, `pnpm build` 통과(큰 번들에 대한 Vite 안내는 남아 있음).
