# 플레이그라운드와 엉덩이 높이 검증

`pnpm dev` 후 <http://localhost:5180/index.html?playground>, 배포 사이트는 <https://inticoy.github.io/snapshoot-classic/?playground>에서 연다. 일반 경기와 동일한 `Game`/`Match`, 카메라, 키보드, 터치 조작을 사용한다.

- 버튼으로 자유 드리블 / 수비수 1명 / 상대 3명 압박 / 15m 패스 받기 / 슬라이딩 태클 / 키퍼 1대1을 선택한다.
- 개인기 탭의 **수비수와 연습해요**를 켜면 기존 1대1 압박 AI의 수비수 한 명을 배치한다. 시범과 R은 선택한 상황을 같은 시드로 초기화하고, 옵션을 끄면 자유 드리블로 돌아간다.
- 개인기 시범은 선수의 실제 별과 경기의 속도 보정을 그대로 사용한다. 별이 부족하면 필요한 별을 안내하고 시범을 실행하지 않아, 직접 입력할 때도 같은 능력치로 연습할 수 있다. 느린 화면 배속은 별도로 적용된다.
- 방향키 이동, E 질주, S 패스, W 스루, A 로빙(수비 시 슬라이딩), D 슛, Space 스탠딩 태클, Z+D 감아차기, Q+D 칩슛, V 카메라, Esc 일시정지.
- R 또는 리셋 버튼은 같은 시나리오의 선수·공·AI·난수·액션과 기록을 초기화한다. 조정한 파라미터는 유지한다. 먼저 필요한 기록을 내보낸다.
- 파라미터를 펼쳐 DRIBBLE 11개 항목과 MOTION_SELECT.windup을 실시간 조정한다. 각도 단위는 rad다. 현재 값 복사는 JSON이며 클립보드 사용이 막히면 선택 가능한 텍스트 상자를 제공한다. 원래 값 버튼으로 페이지 진입 시 값으로 되돌린다.
- 모바일은 가로 화면에서 기존 터치 조이스틱·버튼·스와이프를 사용한다. 패널 제목으로 접어 시야와 조작 영역을 확보한다.

텔레메트리는 고정 스텝마다 수집하고 화면만 10Hz로 갱신한다. 그래프는 시뮬레이션 시간 기준 최근 5초이며 각 항목의 축은 자동으로 맞춘다. 공–발끝 거리는 두 발끝 뼈 중 가까운 월드 거리다. 스킨드 모델이 없으면 경기의 발 기준점을 사용하고, 엉덩이 높이와 모션 id는 미지원으로 남긴다.

전환 시간은 입력 목표 방향이 30° 이상 바뀐 스텝 시작부터 공의 수평 진행 방향이 현재 입력 ±30° 안에 들어올 때까지다. 정지한 공에는 방향을 만들지 않는다. 작은 아날로그 방향 변화도 마지막 목표 대비 누적한다. 입력을 놓거나 조작 선수가 바뀌면 미완료 전환을 취소한다. 터치 빈도는 최근 1초 창이며, 헤비 터치·소유 상실은 조작 선수 기준 누적이다. 의도적 패스·슛 방출은 소유 상실에서 제외한다.

JSON/CSV에는 매 스텝의 월드 XZ 이동 입력, 버튼 held/pressed/released, 선수·공 상태, 소유자, 동작/높이, 터치 사건 수, 계산 수치, 시드, 당시 파라미터와 보정 설정이 담긴다. CSV의 중첩 데이터 셀은 JSON이며 따옴표와 줄바꿈을 인용한다. 기록은 메모리에 쌓이므로 긴 실험은 나눠 내보내고 리셋한다. 스크립트 재생은 아래 JSON 형식으로 한다. 골·아웃·휘슬 뒤에는 재개 배치 없이 동작과 물리를 마저 진행하고 R을 기다린다.

## 높이 수정

`DEF-hips`의 부모는 로컬 Z가 위다. 이전 포맷은 Y만 매 프레임 저장하고 X·Z는 고정해 실제 높이를 잃었다. 이제 `hips`에 xyz를 프레임마다 세 자리 반올림해 저장하며, `MotionClips`가 세 축을 그대로 복원한다. 월드 수평 이동 제거는 기존 `bakeClip(inPlace)`에서만 수행한다.

`npx vite-node scripts/bake-motions.ts`로 로컬 원본을 다시 구웠다. 원본은 커밋 대상이 아니다. 아래 값은 실제 GLB 부모 변환과 AnimationMixer로 확인한 최저 높이다.

| 동작 | 이전 고정 높이 | 수정 후 최저 | 조건 |
| --- | ---: | ---: | ---: |
| grf_sliding_sprint_000 | 0.917m | 0.094m | < 0.45m |
| mc_celebrate_1 | 0.693m | 0.279m | < 0.60m |
| mc_dive_1 | 0.810m | 0.583m | < 0.60m |

다이빙에는 별도의 분류 수정이 포함된다. 기존 `mc_dive_1`의 Save 01 원본은 수직 점프 선방이며, 세 축을 복원해도 최저 0.700m다. 이를 `mc_save_1`로 보존하고, 실제 낮은 옆 선방인 Save 03(종전 `mc_dive_3`)을 `mc_dive_1`로 연결했다. 높이를 인위적으로 줄이는 보정은 추가하지 않았다. 전체 212개 클립과 좌우 반전 동작을 보존했다.

슬라이딩은 핵심 순간 0.320초의 전후 한 프레임(30fps) 안에서도 0.45m 미만이다. 저장 데이터, 복원 트랙, 실제 GLB 월드 높이와 수평 이동 불변을 테스트한다.

## 검증

```bash
pnpm install
pnpm typecheck
pnpm test
pnpm build
# 별도 터미널에서 pnpm dev를 실행한 뒤
pnpm test:playground
```

스모크는 6개 인원 구성, 실제 방향키 전환, R, 슬라이더, JSON/CSV 다운로드, 슬라이딩 높이와 모바일 터치를 확인한다. Chrome for Testing은 `scripts/chrome-path.mjs`를 통해 Playwright 캐시에서 찾는다. 샌드박스에서 실행에 실패하면 미실행으로 보고하고 재시도하지 않는다.

이번 수정에서는 브라우저 스모크를 별도로 실행하지 않았다. WebGL 화면과 모바일 기기에서의 시각 확인은 남아 있다.

최종 검증: `pnpm install`, `pnpm typecheck`, `pnpm test`, `pnpm build` 통과. 21개 테스트 파일, **230개 테스트 통과**. 기존 테스트 기대값은 낮추지 않았다. 빌드에는 기존 500KB 초과 청크 경고가 남아 있다.

## JSON 스크립트 재생

`playground/scripts/`의 JSON을 패널의 **스크립트 실행**에 붙여넣거나 파일 입력/텍스트 영역에 놓은 뒤 실행한다. 화면은 같은 시드와 고정 120Hz 스텝으로 재생한다. **결과 JSON 다운로드**에는 `frames`, `events`, `summary`가 담긴다. 개발자 콘솔에서는 `window.__playground.run(script)`로 같은 결과를 얻는다. 스크립트가 끝나면 화면 조작을 다시 하려면 R로 리셋한다.

헤드리스 실행 예:

```bash
npx vite-node scripts/playground-run.ts playground/scripts/duel.json
npx vite-node scripts/playground-run.ts playground/scripts/duel.json /tmp/duel-result.json
npx vite-node scripts/playground-run.ts 'playground/scripts/*.json' /tmp/playground-results/
```

출력을 지정하지 않으면 파일별 `summary`만 표준 출력에 남긴다. 여러 파일 또는 글롭에 출력 디렉터리를 주면 각 결과를 별도 JSON으로 저장한다. JSON의 `scenario`는 `free`, `duel`, `pressure`, `receive`, `slide`, `keeper` 중 하나다. `seed`는 정수, `duration`은 초, `sampleHz` 기본값은 30이다. `inputs`의 `keys`는 그 시각부터 유지할 **전체 키 목록**이고 `tap`은 한 120Hz 스텝만 누른다. 키 코드는 FC 온라인 배치에 따라 방향키, `KeyE`, `KeyS`, `KeyW`, `KeyA`, `KeyD`, `KeyQ`, `KeyZ`, `KeyC`, `Space` 등을 쓴다. `params`는 `DRIBBLE.touchPeriod`처럼 슬라이더 이름을 접두어와 함께 적는다. `opponent`는 `stand`, `follow`, `press`, `tackle`이며 기본은 `press`다. `control: "opponent"`는 duel, pressure, slide에서 상대 필드 선수를 조작한다. 화면에서 Tab으로도 조작 팀을 바꿀 수 있다.

`summary.possession`은 조작 선수가 공을 소유한 스텝의 비율이다. `progress`는 월드 입력 방향별 투영 이동 거리(m), `alignment`는 해당 방향으로 속도가 30° 이내에 들어올 때까지의 누적 시간(s)이다. `nearestOpponent`는 상대와의 최단 거리(m), `firstWithin2m`는 첫 접근 시각(s)이다. 상대가 없는 시나리오는 둘 다 `null`이다. `userTackles`와 `opponentTackles`는 각각 조작 선수와 상대의 태클 동작 시작 횟수이며, `tackleAttempts`는 두 값의 합계다. `tackleSuccesses`는 성공 이벤트 수, `skills`는 개인기 id별 실행 횟수다. 이벤트의 선수 참조는 이름과 번호로 저장한다.

시드 318, 기본 파라미터, 각 예제의 입력으로 측정한 결과:

| 예제 | 소유율 | 입력 방향 진행 거리 합(m) | 터치 | 소유 상실 | 태클 시도/성공 | 최단 상대 거리(m) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 4방향 전환 | 100% | 29.28 | 43 | 0 | 0/0 | 상대 없음 |
| 180° 반전 | 100% | 23.86 | 33 | 0 | 0/0 | 상대 없음 |
| 1대1 돌파 | 14.7% | 32.66 | 5 | 1 | 1/1 | 0.71 |
| 압박 탈출 | 30.0% | 26.67 | 5 | 1 | 3/1 | 0.69 |
| 슬라이딩 태클 | 0% | 6.63 | 0 | 0 | 1/1 | 0.71 |
| 패스 받기 첫 터치 | 67.7% | 18.62 | 22 | 0 | 0/0 | 상대 없음 |

같은 `ArrowUp` 0–2초, `ArrowRight+KeyE` 2–4초, `ArrowUp+KeyE` 4–6초 입력으로 시나리오만 바꾼 비교:

| 시나리오 | 소유율 | 진행 거리 합(m) | 터치 | 소유 상실 | 태클 시도/성공 |
| --- | ---: | ---: | ---: | ---: | ---: |
| free | 100% | 36.88 | 28 | 0 | 0/0 |
| duel (press) | 14.7% | 32.66 | 5 | 1 | 1/1 |
| pressure (press) | 38.3% | 30.35 | 7 | 1 | 3/1 |

`duel`과 `pressure`에서는 수비수가 접근해 태클을 시도하고 한 번씩 성공한다. 연습 경기에서는 태클 동작 중에도 필드 선수끼리 분리해 몸 간격을 유지한다. 이 수치는 한 시드의 재현 가능한 사례이며 여러 시드의 평균은 아니다.
